rift · design

a local audio daemon, plumbing first

rift is one process, kept running by launchd, that will turn the sound of a room into an append-only log of who said which words when, and play speech back. Today it is the plumbing only: one instance, its socket, the event log, a quiet switch and a clean stop. No audio yet.

today designed paths command line

Today

  • One instance. An exclusive flock held for the process's life; a second serve is refused and logged.
  • The socket. A unix socket in a 0700 directory the daemon checks is this user's, speaking NDJSON: a hello with a protocol number, then health, quiet, feed and shutdown; errors are typed codes (the protocol).
  • The event log. events.ndjson, the only durable state: each event appended whole before any client hears of it. A restart re-derives everything from it, a torn last line cut off.
  • The feed. A connection replays the log from a position and stays live, one gapless sequence; a client that falls 1024 events behind is dropped and resumes from its last position.
  • Quiet. One switch, logged as an event, kept across restarts. It will silence playback; today nothing plays.
  • A clean stop. SIGTERM, SIGINT, SIGHUP and the shutdown request drain alike: stop accepting, log stop, end the feeds, cut open connections after a budget that fits launchd's kill timeout, exit 0.

Designed, not built

The audio path, in the order sound crosses it. Every stage writes its results to the same log, so a client reads the room as events.

stagewhat it does
① deviceseach microphone and speaker is a device rift holds; one on another machine is a later protocol
② one streamevery input resampled onto one clock, so a moment means the same instant on every ear
③ voicesoverlapping speakers split into separate voices, each given an id that holds across the stream
④ wordseach voice transcribed to words, each word with its start and end on that clock
⑤ playbackspeech a client asks for, played on a device and stoppable mid-word, its progress logged

Command line

Releases come from .github/workflows/release.yaml, one per merge to main, YYYY.M.N, signed by packslip.

mise use -g packslip:jgeschwendt/rift   # the latest release, verified by packslip
rift setup                              # into hotswap's layout, the ~/.local/bin/rift link, the agent
rift upgrade --check                    # what the next swap would run
mise run install                        # a checkout: a dev build as ~/.local/bin/rift-next
mise run dist                           # a checkout: this host's release archive, to dist/
commanddoes
rift servethe daemon, in the foreground; launchd runs it
rift statusprints the daemon's health, or {"code":"down","ok":false}
rift quiet on|offsets the quiet switch
rift feed [--after <boot>:<seq>]prints the events, from this boot or after a position, then live
rift setup [--print | --remove]brings the release into hotswap's layout and links ~/.local/bin/rift (with none installed, the latest, through packslip), then writes and loads the agent on that link, or swaps it with one kickstart -k, then waits for the new daemon to answer health ready; --print prints the plist, --remove has hotswap forget the layout and the upgrade agent, unloads the agent and removes the plist and the link
rift upgrade [--check | --back | --retry]hotswap's swap onto a newer release: installed beside the running one, current moved, rift setup, then the smoke (rift version, rift status until the daemon answers with it); a failure rolls back. Exit 0 green or settled, 1 red, 2 unable to try
