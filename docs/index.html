rift · design

a local audio daemon

rift is one process, kept running by launchd, that will turn the sound its devices hear into an append-only log of which words were said when, and play speech back. Today: one instance, its socket, the event log, and the stream, every connected device's sound on one clock, kept on disk for a window, then archived. A device plays a file or, on macOS, hears a microphone, under an identity of rift's own that keeps the microphone's grant across upgrades.

Today

  • One instance. An exclusive flock held for the process's life; a second serve is refused and logged.
  • The socket. A unix socket in a 0700 directory the daemon checks is this user's, speaking NDJSON: a hello with a protocol number, then health, quiet, feed, shutdown and the stream's ops; errors are typed codes (the protocol).
  • The event log. events.ndjson, the durable state beside the audio: each event appended whole before any client hears of it. A restart re-derives everything from it, a torn last line cut off.
  • The stream. Below: devices, tracks, one clock, segments, holes, a window, an archive, readers.
  • The feed. A connection replays the log from a position and stays live, one gapless sequence; a client that falls 1024 events behind is dropped and resumes from its last position.
  • Quiet. One switch, logged as an event, kept across restarts. It will silence playback; today nothing plays.
  • A clean stop. SIGTERM, SIGINT, SIGHUP and the shutdown request drain alike: stop accepting, close the open segments, log stop, end the feeds, cut open connections after a budget that fits launchd's kill timeout, exit 0.

The stream

Mechanical: it carries sound onto one timeline and keeps it a while, and decides nothing about what the sound is. The wire is the protocol's.

  • Devices. A device is a client of the socket, never inside the daemon: it says it is an ear (what it hears) or a mouth (what it plays, as played) and its name, answers the daemon's clock pings, and streams 20 ms frames stamped on its own clock.
  • One clock. The daemon measures each device's offset by ping on connect and again as it streams, and places every frame on its own timeline; events carry that time.
  • On disk. Each track's frames append to 10 s segments, each closed one an event; a gap is a hole event and writes nothing. After a kill the next boot cuts a torn segment to whole frames and closes it: a restart loses at most the frames not yet written.
  • The ears. One switch opens and closes the stream, kept across restarts; closed, devices stay connected and are told, and their frames are refused.
  • Window and archive. A window (default 600 s) and an optional archive directory, both kept; a closed segment older than the window moves to the archive with an index line, or is deleted with none. Nothing deletes from the archive.
  • Readers. A range read streams from disk with silence for holes; a live follow gets each frame as it is placed, within a frame plus transit.

The microphone

rift device ear <name> --mic [<microphone>], macOS only (CoreAudio through cpal, capture alone: no echo cancelling, no voice processing). On Linux it exits 2 saying so.

  • Which input. Alone, --mic follows the system's default input, listed every $RIFT_POLL_MS; a change closes the microphone and opens the new default. With a name it holds that input, matched exactly, and never follows the default. An input not present (the named one, or no default at all) is one stderr line listing the inputs present, then a wait: it opens when the input appears, and closes when it goes, or falls silent a poll long and opens afresh. Two devices, each pinned, record two microphones on two tracks at once.
  • Open only while the ears are. The microphone opens when the ears open and closes when they close, so the system's recording indicator shows exactly when rift hears.
  • One microphone a segment. Every frame names its microphone; a change closes the open segment, and the next opens with a hole and carries the new name, as do its segment event and the archive's index line. The recorded audio separates by microphone with no guessing (the protocol).
  • Conversion. Channel 0 of whatever the input delivers (a sum of channels would cancel or clip), through a Hann-windowed sinc low-pass under 7 kHz, a millisecond each side, then read at 16 kHz between the filtered samples; 16-bit, 20 ms frames, stamped as a file-fed device stamps them, from its first sample other than exact zero. Pings are answered as they arrive, on the thread that reads them: a pong held up by an open or a listing would place frames early by half its delay, and leave that much hole at the next ping.
  • A withheld grant is said, never fatal. Under launchd an ungranted microphone either blocks the open while macOS's prompt waits or delivers exact zeros with no error. An open past $RIFT_OPEN_MS (10 s) is named and waited on: Allow returns it and recording starts. Exact zeros for $RIFT_ZERO_MS (2 s) after an open, an input silent a poll long and a refused open (rift device: "<microphone>": <cause>) close it; the next open waits $RIFT_POLL_MS (1 s), doubled per failure in a row to 64 s. Zeros are never sent, so an unheard input is a hole, not silence on disk. Each line, naming System Settings › Privacy & Security › Microphone where the grant is the cause, is said once until the input is heard; the ears close and open throughout, and the device exits only with its connection.

Identity

macOS grants the microphone to a program by its code signature: an ad-hoc signature changes with every build, so every upgrade would ask again. rift signs itself with a certificate of its own, and the grant, which names the identifier and the certificate, survives.

  • The Info.plist. Linked into the binary on macOS (__TEXT,__info_plist): CFBundleIdentifier dev.gigantic.rift, CFBundleName rift and the sentence the microphone's prompt shows.
  • What setup makes, once. After hotswap links the release and before the daemon is loaded or swapped: a password in <root>/rift.keychain-pass (0600), a keychain <root>/rift.keychain-db with no lock timeout and none at sleep, kept off the search list, and in it a self-signed code-signing certificate, CN=rift, RSA 2048, 100 years, its key usable by codesign with no prompt. Each run unlocks the keychain (a reboot locks it) and signs the release itself, the file behind current, with identifier dev.gigantic.rift, unless that identity already signed it: a copy beside it is signed, then renamed over it, so a running rift keeps the file it mapped. Each tool call has $RIFT_SIGN_MS; one that would ask at the screen is killed and named, and a failure is rift setup: <line>, exit 1, before the daemon is touched.
  • What --remove deletes. The keychain and its password file, as files; the root is left. The next setup makes a new certificate, so the microphone is asked for again.

The path

The audio path, in the order sound crosses it, part built. Every stage writes its results to the same log, so a client reads the sound as events.

stagewhat it does
① devicesclients of the socket, each an ear or a mouth; built: a file player and, on macOS, the microphone (rift device); next, a standing launchd job for the ear, then the mouth, playing what it is given; one on another machine is a later protocol
② one streambuilt: every track on the daemon's clock, so a moment means the same instant on every track (the stream)
③ voicesoverlapping speakers split into separate voices, each given an id that holds across the stream
④ wordseach voice transcribed to words, each word with its start and end on that clock
⑤ playbackspeech a client asks for, played on a device and stoppable mid-word, its progress logged

Command line

Releases come from .github/workflows/release.yaml, one per merge to main, YYYY.M.N, signed by packslip.

mise use -g packslip:jgeschwendt/rift   # the latest release, verified by packslip
rift setup                              # into hotswap's layout, the ~/.local/bin/rift link, the agent
rift upgrade --check                    # what the next swap would run
mise run install                        # a checkout: a dev build as ~/.local/bin/rift-next
mise run dist                           # a checkout: this host's release archive, to dist/

rift device ear|mouth <name> <file.pcm> [--fast]a device, its own process: plays a raw PCM file (16 kHz, mono, 16-bit little-endian) as the track's frames, a short tail dropped, answering every ping, paced in real time and stamped from now, a pause or clock step of over 100 ms playing on from the clock as a hole, or with --fast sent as fast as each is answered and stamped as if captured ending now; prints its reply, then each notice and refusal; exit 0 once every frame is answered, {"code":"unknown","ok":false} and exit 1 if the connection ends first; an unreadable file is rift device: <cause>, exit 1

rift setup [--print | --remove]brings the release into hotswap's layout and links ~/.local/bin/rift (with none installed, the latest, through packslip), signs the release with rift's identity, then writes and loads the agent on that link, or swaps it with one kickstart -k, then waits for the new daemon to answer health ready; --print prints the plist, --remove has hotswap forget the layout and the upgrade agent, unloads the agent and removes the plist, the link, the keychain and its password
rift upgrade [--check | --back | --retry]hotswap's swap onto a newer release: installed beside the running one, current moved, rift setup, then the smoke (rift version, rift status until the daemon answers with it); a failure rolls back. Exit 0 green or settled, 1 red, 2 unable to try
